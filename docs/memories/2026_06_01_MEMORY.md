# Session Memory — 2026-06-01

## Headline
Built the **rate-us** flow. A new Vue overlay (`src/components/RateUs.vue`)
auto-prompts after enough completed puzzles, with sane gating to avoid
nagging. Companion bookkeeping fields landed in `src/services/settings.js`.

## What was added

### `src/components/RateUs.vue` (new)
- Fullscreen overlay matching the world: sky-blue → cream gradient,
  drifting clouds, twinkling sparkles, and the same animated sun mascot
  SVG used by `Onboarding.vue` / `Paywall.vue`.
- 5 big animated stars, headline **"Loving Toddler Puzzles?"**, friendly
  body copy.
- Three CTAs:
  - Primary **"Rate the app"** → `InAppReview.requestReview()`, then marks
    `rateUsRated = true` (the OS prompt never tells us if the user
    actually rated — optimistic suppression avoids a double-ask).
  - Secondary **"Maybe later"** → stamps `rateUsDismissedAt = Date.now()`.
  - Tertiary **"Don't ask again"** → marks rated (equivalent suppression).
  - Top-right **X** behaves like Maybe later.
- **Safety net:** if `InAppReview.requestReview()` throws OR the iOS
  promise never resolves, the overlay auto-closes after 8 s so a broken
  plugin can't trap the toddler. On web/dev we fake a 600 ms delay so the
  flow is testable in the browser.
- Event protocol:
  - `EventBus.on('rate-us:check')` — runs gating, opens only if rules pass.
  - `EventBus.on('rate-us:open')` — debug/test entry, opens unconditionally.
  - `EventBus.emit('rate-us:closed', { rated })` on every close.

### `src/services/settings.js` (extended)
Four new cache fields + persisted keys. Same getter/async-setter pattern
as the existing entries; `notify()` fires on every setter so any future
subscriber (e.g. Settings UI showing "you've rated us") would auto-update.
- `rateUsPromptCount` (number, default 0) + `setRateUsPromptCount`.
- `rateUsRated` (boolean) + `setRateUsRated`.
- `rateUsDismissedAt` (epoch ms) + `setRateUsDismissedAt`.
- `puzzlesCompleted` (number) + `setPuzzlesCompleted` +
  `incrementPuzzlesCompleted()` convenience that bumps the in-memory
  cache first, then persists, so the synchronous getter returns the
  fresh value immediately.

### `src/game/levelComplete.js` (instrumented)
At the END of `showLevelComplete()`'s onComplete callback (after the
scene transition kicks off), we now:
1. Call `settings.incrementPuzzlesCompleted()` (best-effort, no await of
   the result blocks anything).
2. Emit `EventBus.emit('rate-us:check')` so `RateUs.vue` decides.
Done after `onComplete` so the next scene starts loading first; the
rate prompt then layers on top without blocking the transition.

### `src/App.vue` (mount)
- Imports + mounts `<RateUs />` alongside `<Onboarding />` and `<Paywall />`.

## Gating rules (in `RateUs.vue::shouldPrompt()`)
Skip the prompt if **any** of these:
- `rateUsRated === true`                              (one-time only)
- `rateUsPromptCount >= 3`                            (give up after 3)
- `Date.now() - rateUsDismissedAt < 3 days`           (cooldown)
- `puzzlesCompleted < 3`                              (no first-puzzle ask)

Otherwise: open the overlay AND immediately bump `rateUsPromptCount` (so
a crash mid-prompt still consumes that show).

## Open follow-ups / notes
- The Settings scene already has a `buildRateUsCard()` (Phaser version)
  that calls `appReview.requestReview()` / `appReview.openStoreReview()`
  directly. That entry point is intentionally untouched — it remains the
  always-available manual trigger. It does not touch the new
  `rateUsRated` flag; if we ever want "tapped manual card also counts as
  rated", wire it through `settings.setRateUsRated(true)` there too.
- The prompt count is bumped per-show, not per-session, so toddlers who
  blitz through 3 puzzles see the prompt only once. After "Maybe later",
  the 3-day cooldown prevents the next bump.
- `puzzlesCompleted` is a lifetime counter — never reset on install
  upgrades. If we ever want a "fresh start" debug switch, add a
  `setPuzzlesCompleted(0)` toggle to the Settings debug section.
- `MAX_PROMPTS = 3`, `MIN_PUZZLES_BEFORE_PROMPT = 3`,
  `DISMISS_COOLDOWN_MS = 3 days`, `NATIVE_PROMPT_TIMEOUT_MS = 8 s` —
  all tweakable at the top of `RateUs.vue`. No env wiring; tune in code.
