## Falling puzzle pieces (physics) — all matching games

New shared helper `src/game/pieceDrop.js` (`dropPieces(scene, animalObjects)`
+ `applyEarthGravity`). On load the draggable pieces now spawn above the top
edge and rain down under gravity, bounce a little (BOUNCE 0.22), collide with
each other so none ever overlaps/stacks, and settle in a pile along the bottom.
Drag handling: held piece ignores gravity + is immovable; a misdrop falls back
to the pile; a correctly-placed (locked) piece freezes on its shadow. "Locked"
is detected via `obj.input.enabled === false` (the scenes call
`disableInteractive()` on a correct match).

"Earth gravity": arcade world has no length scale, so we treat the screen as
~4.5 m tall (`SCREEN_METRES`) → pixels/m = sHeight/4.5 → gravity =
9.81 * pixels/m. Acceleration is physically exact; ~1 s top-to-bottom fall.
Gravity is set per-scene on `scene.physics.world.gravity.y` (global config
still has the old `y:300` default, unused elsewhere).

Wired into the 7 shadow-matching scenes that share the
`addAnimals → setDraggable → drag/dragend → isAnimalOnBase` pattern:
GameA (Toys), GameB (Heroes), GameC (Faces), GameD (Fruits), GameE (numbers),
GameF (letters), GameG (shapes). Each got an import + a single
`dropPieces(this, animalObjects)` call at the end of `addAnimals`.

NOT touched (different mechanics, "fall to ground" doesn't apply): GameH,
GameI (sort-into-bins, has its own bounce-back), GameJ.

Relies on arcade bodies being scale-aware (Phaser 3.60+; repo is 3.85), so the
default body matches the scaled display size — no manual setSize needed.

Verified: `vite build` compiles clean, helper bundled, 7 call sites present.
NOT yet verified at runtime in a browser/device — physics feel (fall speed,
bounce, pile height vs. shadow positions) should be eyeballed on `npm run dev`.
