# 2026-06-06 session

## Orientation responsiveness (rotation now reflows the game)

Problem: on a physical device, rotating portrait↔landscape left the layout
squished/cropped (MainMenu cards overflowed). Root cause: the canvas is created
with `Phaser.Scale.NONE` and a FIXED size in `src/game/main.js`
(`innerWidth × DPR` / `innerHeight × DPR`, frozen at startup). Scale.NONE does
not track the viewport, so rotation never resized the canvas. The native shells
DO allow rotation (Android `configChanges` includes `orientation`; iOS Info.plist
lists Landscape orientations).

Decision: make it responsive (user chose this over locking to portrait).

Implementation: new `src/game/responsive.js`, `installResponsive(game)`, called
once from `StartGame` in `main.js`. On a true portrait↔landscape FLIP it:
1. `game.scale.resize(innerWidth*DPR, innerHeight*DPR)` (preserves the config
   `zoom: 1/DPR` retina setup and re-applies autoCenter).
2. Restarts the live scene(s) via `game.scene.getScenes(true).forEach(s =>
   s.scene.restart())`.

Why restart instead of per-scene reposition: every scene lays out
proportionally from `cameras.main.width/height` (read fresh in each
preload()/create()), and `pieceDrop.js` re-sets the Matter world bounds from
`scene.sWidth/sHeight` on every run. A restart therefore reflows the WHOLE scene
(decorations, grids, physics) at the new dimensions with zero per-scene code,
across all 14 scenes. All transitions use `this.scene.start(...)`, so exactly
one scene is active at a time.

Key guard: react ONLY to an orientation flip (`landscape` boolean change), never
to in-orientation size changes. The Settings toddler-name `<input>` opens the
soft keyboard, which can shrink `innerHeight`; restarting there would bounce the
keyboard and wipe the field. Orientation-flip-only sidesteps that on both iOS and
Android. Debounced 220ms (`SETTLE_MS`) because rotation fires a burst of events
and innerWidth/innerHeight can lag a frame.

DPR is recomputed in responsive.js (`Math.min(devicePixelRatio, 2)`) to match
main.js. If main.js ever changes the DPR cap, update responsive.js too.

Tradeoff (accepted): rotating mid-puzzle restarts that puzzle, since the live
scene is rebuilt. Fine for a 2–4 yr-old game with no score/lives. True
state-preserving reflow would mean serialising/rehydrating per-scene state
across all scenes — not done.

Verified: `npm run build-nolog` clean. NOT yet eyeballed on a physical device —
rotate on device and confirm MainMenu + a game scene + Settings all reflow.
After confirming, run `npm run cap:sync` to push `dist/` into the native
projects.
