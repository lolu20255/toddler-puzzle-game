# Session Memory — 2026-05-26

Long running session that picked up where `2026_05_21_MEMORY.md` (menu) and
`2026_05_23_MEMORY.md` (Capacitor wrap) left off. The game went from "wraps in
Capacitor but renders broken on device" to a polished bilingual app with
settings, real TTS audio, the right asset pipeline, and four levels.

## Headline state of the codebase right now

- **Stack:** Vue 3 + Vite 5 + Phaser 3.85 wrapped with Capacitor 7. iOS +
  Android native projects committed under `ios/` and `android/`.
- **Bundle id:** `com.blackboxcode.toddlerpuzzle`, display "Toddler Puzzles".
- **Scenes:** `Boot` → `MainMenu` → `Settings` / `GameA` / `GameB` / `GameC` /
  `GameD` → `GameOver`.
- **Native services** in `src/services/`: `platform`, `storage`, `settings`,
  `haptics`, `purchases`, `notifications`, `appReview`, `analytics`,
  `native` (orchestrator), and `libro/{http,auth,pronunciation,index}` for the
  TTS backend.

## What was built (chronological, all in this session arc)

### Rendering pipeline correctness (the device build was broken before this)
- **Viewport meta** `initial-scale=1.0, viewport-fit=cover` (was `0.5` — the
  whole reason "the menu looked weird on device" in earlier screenshots).
- **`public/style.css`** rewritten — `100dvh`, `touch-action: none`,
  `overscroll-behavior: none`, sky-blue body bg to hide any sliver of
  margin during launch.
- **`src/game/main.js`** — Phaser config switched to
  `Scale.NONE` with `width × DPR / height × DPR / zoom 1/DPR`. **DPR is
  capped at 2** (not 3) — the iPhone Pro Max canvas at DPR=3 was OOM-killing
  the WKWebView WebContent process on real device even though it was fine
  on simulator.
- **`src/game/scenes/Boot.js`** — `loadGameAssets()` moved into `preload()`
  and runs **unconditionally**. The original gated it behind a Google Fonts
  WebFont.js callback; on iOS Safari the CDN often hits `inactive`, so the
  game would launch with zero textures (Phaser's green-outlined `__MISSING`
  placeholder showed everywhere).
- **`index.html`** — fonts now load via standard `<link rel="stylesheet">`
  from Google Fonts (with `preconnect`), and Boot waits on
  `document.fonts.ready` + a 2 s safety timeout.

### initNative defence-in-depth
- `src/services/native.js` runs each native plugin call inside a `step(name, fn)`
  wrapper (logs + per-step try/catch). `App.addListener('backButton', …)` is
  guarded to **Android only** — calling it on iOS killed the WebContent
  process on the user's device.
- `src/services/notifications.js` `initialize()` is a deliberate no-op now —
  `PushNotifications.*` is **lazy-imported and never called until
  `requestPushPermission()`** so the missing iOS Push Notifications
  entitlement can't crash the launch.

### Celebration modal (the heart of the gameplay loop)
- `src/game/celebrate.js` — new `showCelebration(scene, assetKey)` builds a
  yellow card with the matched picture + types its word out letter-by-letter.
  Two audio fetches in parallel from libro:
  1. spelling `"M, A, N, G, O"` — used to derive `perLetterMs` from the
     spelling-audio's actual `audio.duration`, so the visual letter pops
     stay in sync no matter how fast/slow TTS speaks
  2. word + praise `"MANGO. Good job <name>!"` — chained to start on the
     spelling audio's `ended` event
- `src/game/itemNames.js` is the lookup: `asset_<pack>_<letter>` → readable
  word, **now per-language** (`ITEM_NAMES.en` + `ITEM_NAMES.es`,
  `nameForAssetKey(key, lang)` with English fallback).

### libro-ai TTS backend (`src/services/libro/`)
- Device-based auto-auth mirroring the libro-ai-app pattern. Token cached
  in Capacitor Preferences. Memoised `ensureAuthenticated()`.
- **API URL via env** — `.env` (gitignored, defaults to localhost or a
  user-set ngrok URL) and `.env.production` (committed, prod). Vite picks
  the right one based on mode. `http.js` logs the resolved base URL in dev.
- `pronunciation.js` posts to `/v1/pronunciations` with `{word, language,
  provider}`. Cache key `<provider>:<lang>:<word>` matches the backend's
  `storage/words/<provider>/<lang>/<word>.mp3` layout.
- **Provider** defaults to `elevenlabs` (voice `NoOVOzCQFLOvtsMoNcdT`),
  overridable per call or via `VITE_LIBRO_PRONUNCIATION_PROVIDER`.

### Settings scene (today's main thrust)
- Cog **top-right** of MainMenu (iOS/Android convention). **Important
  implementation detail**: the gear visuals live in a Container, but the
  interactive element is a separate transparent `Phaser.Rectangle` on top.
  Container input was unreliable in this Phaser/iOS WebView combo — taps
  near the top of the canvas never fired `pointerdown` even though
  `hitTestPointer` found the container. Plain Rectangle input always works.
  Same pattern reused on every Settings interactive (back button, language
  pills, toggle).
- `src/services/settings.js` — Capacitor-Preferences-backed cache with
  sync getters (`toddlerName()`, `hapticsEnabled()`, `language()`),
  async setters, and an `onChange()` subscriber API.
- `src/services/haptics.js` — every method gates on
  `isNativePlatform() && settings.hapticsEnabled()` so the toggle takes
  effect immediately, no scene restart.
- App version surfaces via **Vite `define`** of `__APP_VERSION__` from
  `package.json#version` (cleaner than runtime JSON import).
- `Settings.js` (v2) is three consistent white-card sections — TODDLER'S
  NAME, LEARNING, Vibration — with the language picker showing two
  raised yellow pills (English / Español) and a hint *"Puzzle audio will
  be spoken in this language"*.

## How the bilingual flow works end-to-end

A toddler matches a bear with the language set to Spanish:

1. `GameA.dragend` → `showCelebration(scene, 'asset_animal_cartoon_h')`
2. `celebrate.js` reads `settings.language()` → `'es'`
3. `nameForAssetKey('asset_…_h', 'es')` → `'OSO'`
4. `buildPraise('es')` → `'Muy bien, Lucia!'` (or `'Muy bien!'` with no name)
5. Two parallel POSTs to `/v1/pronunciations`:
   - `{word: "O, S, O", language: "es", provider: "elevenlabs"}`
   - `{word: "OSO. Muy bien, Lucia!", language: "es", provider: "elevenlabs"}`
6. Spelling audio's `audio.duration` drives the visual letter reveal.
7. Spelling audio `ended` → word+praise audio plays.

## Gotchas to remember

- **Don't put interactive elements at the very top of the canvas.** iOS
  WKWebView (and Phaser's input through it) drops pointer events very close
  to the top edge. Push interactive zones at least ~6% of the min side
  inside.
- **Don't use a Container as the interactive target** — Container input has
  been flaky here. Use a transparent `Phaser.Rectangle` layered on top of
  the visuals.
- **Don't gate asset loading on a font CDN callback.** Load assets in
  `preload()` unconditionally.
- **Cap DPR at 2** for the canvas backing store on iOS or you risk WebContent
  OOM kills.
- **iOS Capacitor with the wrong Push entitlement crashes the WebContent
  process.** `PushNotifications.checkPermissions()` is enough to do it — keep
  it lazy-imported.
- The libro API endpoint expects ISO-639-1 codes (`en`, `es`), lower-case.
